Architecture overview

English Trainer System Map

A practice app for Hebrew-speaking students: English grammar and vocabulary plus a Math tab, used in the browser and from Telegram (vocabulary and lesson exercises). Three services on Google Cloud share one API and one student database.

Services

What each service owns

Ownership means the data and decisions a service is responsible for. Nothing else may change them.

Web app

frontend/
Owns
Everything the student sees in the browser, and the login token kept on the device.
Main functions
  • Login and registration
  • English and Math topics, lessons with animated explanations
  • Exercises with feedback, mistakes review, progress and points
  • Vocabulary quiz and history
  • Telegram page: issue a link code, unlink

Trainer API

backend/
Owns
All student data and every rule: who the user is, which answer is right, points, levels, limits.
Main functions
  • Accounts and JWT authentication
  • Lessons and exercises from bundled content, answer checking
  • Progress, points, achievements, daily challenges
  • Vocabulary quiz, word scores, failed words, review mode
  • Answer check: a Hebrew answer that misses the dictionary gets one yes/no from Gemini
  • Bot API: vocabulary and lesson-exercise sessions, chat linking, service key, rate and daily caps

Telegram bot

bot/
Owns
The conversation only: reading Telegram messages, choosing the API call, writing the Hebrew reply. It stores no student data.
Main functions
  • Verifies the Telegram webhook secret
  • Link code, commands, level choice, lesson pick and answers go straight to the API
  • Other messages go to an ADK agent whose tools call the API
  • Turn, token and call caps before any model use

Main flows

Sequence diagrams at service level. Endpoint details live in the code and in the repo docs.

Web app

Practise a lesson in the browser

The student logs in once, then every call carries the token. The API checks answers and awards points; the browser only displays.

  W->>A: Login with name and password
  A->>D: Find user, check password
  A-->>W: JWT token
  S->>W: Open a topic and lesson
  W->>A: Get lessons and exercises
  A-->>W: Content from the bundled JSON
  S->>W: Answer the exercises
  W->>A: Submit answers
  A->>A: Check answers, count score
  A->>D: Save result, mistakes, points
  A-->>W: Score, feedback, explanations
  W-->>S: Results page
Web app + Telegram

Link a Telegram chat to a student

The code is issued to the logged-in student, so the chat that sends it becomes that student. Codes last 10 minutes, work once and are stored only as a hash.

sequenceDiagram
  actor S as Student
  participant W as Web app
  participant A as Trainer API
  participant T as Telegram
  participant B as Bot service
  S->>W: Open the Telegram page
  W->>A: Request a link code, with JWT
  A-->>W: 6-digit code
  S->>T: Send the code to the bot
  T->>B: Webhook with secret token
  B->>A: Link chat, with service key
  A->>A: Match code, store chat to student
  A-->>B: Linked
  B->>T: Connected, send words to start
Telegram bot

A vocabulary session in Telegram

The bot asks the level, then sends 20 words from the whole vocabulary. Failed words come back shuffled until none are left. The API scores every answer; a Hebrew answer that misses the dictionary is first checked by the API with Gemini. "?" shows an example sentence for the current word.

sequenceDiagram
  actor S as Student
  participant B as Bot service
  participant A as Trainer API
  participant G as Gemini
  participant D as Firestore
  S->>B: מילים
  B->>A: Start session
  A-->>B: Which level
  B-->>S: Easy, medium or hard, with buttons
  S->>B: 1
  B->>A: Answer
  A->>A: Pick 20 words at that level
  A-->>B: First English word
  B-->>S: Translate to Hebrew
  loop Each word, then rounds of failed words
    opt Student sends ?
      S->>B: ?
      B->>A: Answer
      A-->>B: Example sentence, same word
      B-->>S: Example sentence
    end
    S->>B: Hebrew answer
    B->>A: Answer
    opt Answer misses the dictionary
      A->>G: Is this translation acceptable
      G-->>A: Yes or no
    end
    A->>D: Word score, failed word, points
    A-->>B: Right or wrong, next word
    B-->>S: Verdict with points, next word
  end
  A-->>B: Summary
  B-->>S: Rounds, right and wrong, points earned
Telegram bot

A lesson's exercises in Telegram

English or Math: the next lesson, or one picked from a numbered list. The API freezes the lesson's 10 questions in the bot session; a multiple-choice answer is the option number 1–4. The last answer is graded by the same exercise service as the web, so score, points, mistakes and progress match. No model is involved.

  participant B as Bot service
  participant A as Trainer API
  participant D as Firestore

    S->>B: תרגיל אנגלית
    B->>A: Start exercise (subject)
  else Pick from the list
    S->>B: שיעורים חשבון
    B->>A: Lesson list (subject)
    A-->>B: Numbered page, passed and next marked
    B-->>S: List with more / back buttons
    S->>B: Lesson number
    B->>A: Answer
  end
  A->>A: Choose 10 questions like the web
  A->>D: Exercise session
  A-->>B: First question
  B-->>S: Question, options 1–4 as buttons
  loop Each question
    S->>B: Option number or text
    B->>A: Answer
    A-->>B: Right or wrong, explanation, next question
    B-->>S: Verdict, next question
  end
  A->>D: Result, points, mistakes, progress
  A-->>B: Score, points, next lesson
  B-->>S: Summary

Guardrails

Security and cost limits

One owner for data

Only the API touches Firestore. The database rules deny all direct client access.

Every call authenticated

Students use a JWT. The bot uses a service key plus a linked chat. Telegram must present the webhook secret.

The model has narrow jobs

Words, points and counters come from the API. Gemini routes free-form messages and gives a yes/no on answers that miss the dictionary, nothing else.

Hard caps

60 messages per minute per chat, 300 per student per day, 2 bot instances, 100 answer checks per student per day, bounded tokens and calls, and a monthly budget alert.

Detailed references in the repository: docs/deployment.md for operations and docs/telegram-bot.md for the bot, its caps and troubleshooting.
